# AUTHENTICATION

پیاده‌سازی Phase 1، مبتنی بر Supabase Auth (AD-003). بدون پروتکل رمزنگاری سفارشی.

## حالت‌های ورود

1. **Guest Mode (AUTH-001)** — کاربر بدون هیچ ثبت‌نامی وارد اپ می‌شود. یک شناسه‌ی مهمان محلی (`getOrCreateGuestId`) ساخته/بازیابی می‌شود. داده‌ی مهمان محلی ذخیره می‌شود. کاربر هیچ‌وقت مجبور به ورود فوری نمی‌شود.
2. **Email/Password (AUTH-002)** — ثبت‌نام با `supabase.auth.signUp`، ایمیل تأیید به‌صورت خودکار توسط Supabase ارسال می‌شود. ورود با `signInWithPassword`.
3. **بازیابی رمز عبور** — `resetPasswordForEmail` سپس `updateUser({ password })` پس از باز شدن نشست بازیابی از لینک ایمیل.

## مدیریت نشست (AUTH-003)

نشست فعلی از طریق `auth.getSession()` خوانده می‌شود. اطلاعات نشست (accessToken، refreshToken، expiresAt) در `AppSession` (دامنه) نگه‌داری می‌شود — نه در localStorage خام.

## مهاجرت داده‌ی مهمان (AUTH-005)

وقتی یک مهمان ثبت‌نام/ورود می‌کند، `AuthService.upgradeGuestToAccount(guestId, newUserId)` باید فراخوانی شود تا داده‌ی محلی مهمان به حساب جدید منتقل شود. **این متد هنوز پیاده‌سازی واقعی ندارد** — چون به شمای ذخیره‌سازی محلی (SQLite/IndexedDB، Phase 9) وابسته است. تا آن زمان پرتاب خطا می‌کند تا کسی تصور نکند این قابلیت کار می‌کند (مطابق قانون "بدون پیاده‌سازی جعلی").

## ابطال نشست بر اساس دستگاه (AUTH-004)

Supabase Auth SDK فقط امکان خروج از *نشست فعلی* را می‌دهد. ابطال نشست یک دستگاه خاص نیاز به جدول اختصاصی `user_sessions` + یک Edge Function دارد که هنوز ساخته نشده — پیگیری در REQUIREMENTS_TRACEABILITY.md.

## وضعیت این سند

Phase 1 — نسخه‌ی اولیه. MFA و OAuth در فازهای بعدی طبق نیاز اضافه می‌شوند (بخش ۲۱ سند اصلی: اختیاری).
