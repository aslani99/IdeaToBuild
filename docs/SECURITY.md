# SECURITY

امنیت یک ویژگی محوری محصول است، نه یک لایه‌ی اضافه‌شده. هرگز ادعای "۱۰۰٪ امن" مطرح نمی‌شود — به‌جای آن، کنترل‌های امنیتی قابل‌سنجش پیاده و به‌طور مداوم بررسی می‌شوند.

## اصول

- Zero Trust
- Defense in Depth
- Least Privilege
- Secure by Default
- Fail Closed
- OWASP ASVS

## احراز هویت (Phase 1)

- ایمیل/رمز عبور، تأیید ایمیل، بازیابی رمز عبور
- مدیریت نشست امن، ابطال نشست، مدیریت دستگاه/نشست
- MFA اختیاری، OAuth در صورت نیاز
- **بدون پروتکل رمزنگاری سفارشی** — فقط از کتابخانه‌ها و استانداردهای تثبیت‌شده (Supabase Auth)

## Guest Mode

اپلیکیشن کاربر را مجبور به ورود فوری نمی‌کند. کاربر می‌تواند به‌عنوان مهمان وارد شود؛ داده‌ی مهمان محلی ذخیره می‌شود و بعد از ثبت‌نام قابل انتقال به حساب است — بدون حذف ناگهانی.

## تفویض اختیار (Authorization)

- Row Level Security در Postgres برای هر منبع متعلق به کاربر
- هرگز اعتماد به user ID / workspace ID / resource ID ارسالی از کلاینت — همیشه تأیید سمت سرور

## رمزنگاری

- رمزنگاری در انتقال (TLS) و در حالت سکون
- پشتیبانی از رمزنگاری سمت کلاینت (End-to-End) برای داده‌ی حساس در فازهای بعدی
- کلید رمزنگاری هرگز در کد منبع، لاگ، یا دیتابیس plaintext ذخیره نمی‌شود

## امنیت فایل

هر فایل آپلودی نامعتبر فرض می‌شود تا اثبات خلاف آن. محافظت در برابر: فایل/آرشیو مخرب، ZIP bomb، جعل MIME، path traversal، نام فایل مخرب. هرگز فایل آپلودی به‌صورت خودکار اجرا نمی‌شود؛ هرگز به پسوند یا MIME گزارش‌شده توسط کلاینت اعتماد نمی‌شود.

## امنیت Tauri

Capabilities محدود و مبتنی بر least-privilege؛ بدون دسترسی نامحدود فایل‌سیستم، بدون اجرای دلخواه shell/command.

## لاگ‌گیری

هرگز در لاگ ذخیره نمی‌شود: رمز عبور، توکن دسترسی/رفرش، کلید رمزنگاری، کلید بازیابی، محتوای خصوصی کاربر.
